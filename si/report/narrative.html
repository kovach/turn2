A formalization study

Spirit Island in Turn

Can the rules of a large, heavily expanded board game be written so that each Turn rule matches one rulebook sentence, and every expansion, card and spirit is added without rewriting what came before?

Summary Reading Turn The base rules First extensions Extension patterns All spirits Language findings What to change Appendix

Summary

Mostly yes, if the base is written for it. All 37 spirits' special rules were written as separate files on top of one base slice. Of 67 rules, none needed rewriting the base except three (two spirits). Nineteen are partial: the core of the rule works, but some clause needed a feature Turn doesn't have.

The additions only went in cleanly where the base exposed the right hook: a named view for each noun the rulebook uses, a summed relation for each quantity, its own episode for each verb, and a name for each choice. Where the base hadn't done that, the addition needed a base change or stayed partial.

The most common problems were not about individual rules:

  • Simultaneity. Rules that fire at the same moment cannot see each other's effects. The rulebook says “in any order you choose”. Turn's default is “all at once”.
  • Optional replacements. Turn exceptions always fire. Rules like “you may … instead” need the decision asked in an earlier step.
  • No notion of an Action. “Once per Action” and “at the same time” have nothing to key on.
  • Silent timing mistakes. Several first attempts ran without errors but read state from the wrong moment.

Each of these has a concrete language change proposed in What to change.

Reading Turn

Turn derives tuples that live on intervals of a partial order of moments. Episodes are tuples with a duration; a rule body reads left to right, matching tuples and asserting new ones, and by default the rest of the body runs inside what it matched. The full language is described in discussions/turn-tutorial.md (source). The code in this report uses an invented highlighting scheme that colors each sigil by what it does:

~launch an episode
~> >launch / match, then continue after it
+assert a fact (lasts to the end of time)
^assert inside the enclosing episode
? !ask a choice / constrain its options
{ => }exception: replace a tuple

#acc @sumdeclaration, aggregation

-- p9comment (usually the rulebook sentence)

Every experiment is a set of .t files concatenated and run headless: run.sh core.t spirit-ocean.t. Player decisions are written as ?[rng] choices with a fixed seed, so a run is reproducible, and several seeds were tried where the choice mattered. All files are in si/ and reproduced in the appendix.

The base rules

The base slice (core.t) covers the Invader Phase (Ravage, Build, Explore), Blight with Presence destruction and cascades, Fear from destroyed Towns and Cities, Defend, the five-phase turn, Elements, Power speed, Push, adding Presence and Sacred Sites. Each rule carries the rulebook sentence it implements. Most read close to the text. Build is two rules, one per sentence:

{{grep core.t 9 -- p10 Build: "Wherever there are Invaders}}

Explore's “you only add one Explorer” falls out of a boolean acc relation, which holds each land at most once:

{{grep core.t 13 -- p10 Explore: "Add an Explorer}}

Blight's two consequences are two rules. The cascade reads has-blight at the start of add-blight, which is exactly “if the land already had Blight”:

{{grep core.t 19 -- p15 "After Setup, whenever you add Blight}}

Simultaneity was the first real bug

The natural reading of “the Invaders Ravage in each land of the shown type” launches one ravage episode per land. Turn makes those siblings: neither can see the other's effects. In a run, l2's Blight cascaded into l1 but could not see the Blight l1's own Ravage had just added, so l1 ended with two Blight and no second cascade, which no real play order allows. The rulebook says Powers resolve “in whatever order the players want”; Ravage needs the same. The fix is a loop that picks the next land:

{{grep core.t 12 -- (sequential variant}}

It works, but it is boilerplate for a very common rulebook idiom (“for each X, in an order you choose”), and the +ravaged marker would leak into the next turn unless keyed by turn.

“When Invaders would X, instead Y” is exactly what exceptions are for. Disease is the rulebook sentence and one line:

Heavy Mining carries its own exception to the Blight rules, and the Turn version has the same shape as the English:

{{grep ext-sweden.t 8 -- Sweden, level 1}}

Words of Warning changes the order of Ravage (“Dahan deal damage simultaneously with Invaders”). It still went in as an addition, because the base names the fight-back step as its own episode that an exception can reroute:

{{grep ext-wow.t 10 -- Words of Warning}}

Badlands failed. “+1 Damage per Badlands” re-emits damage-dahan with a bigger number, and the exception catches its own output forever:

{{grep ext-badlands.t 6 -- JE p7-8, Badlands}}

The fix is in the base: write Damage to Dahan as summed contributions, so Badlands only adds one. Strife works for that reason: the base writes each Invader's damage as its own tuple and sums them. Extensibility depends on the base exposing each quantity the rulebook names.

The game itself is not purely additive either. Jagged Earth's Ravage Timing box says “This a change from existing rules” and reorders Ravage (JE p. 7).

Extension patterns

Across the extensions and all the spirits, an addition hooks into the base in a small number of ways. Each one only works where the base reads the thing through a relation the addition can extend.

Trigger 21 rules

“After X, do Y.” A rule matches the base episode for X and launches Y. Needs X to be its own episode, carrying who caused it.

{{rulecode vengeance|LINGERING PESTILENCE|3}}

Add rows 16 rules

Widen a set or add to a total. Needs the base to read through a relation, never inline.

{{rulecode earth|EARTH'S VITALITY|1}} {{rulecode teeth|TERRITORIAL AGGRESSION|2}}

Exception 13 rules

“When X would happen, instead Y.” Needs X to be a tuple emitted inside a context the rule can name.

{{rulecode mud|OFFER NO FIRM FOUNDATIONS|4}}

Counts as 6 rules

“Your Presence in Wetlands counts as a Sacred Site.” Rows added to a view the base reads everything through.

{{rulecode river|RIVER'S DOMAIN|2}}

New state 5 rules

A new resource or location. Time on Fractured Days' panel is Presence at a location, counted by a sum.

{{rulecode fractured|FRAGMENTS OF SHATTERED TIME|3}}

Narrow a choice 4 rules

An extra ! on a named choice. Constraints are conjunctive, so they can only remove options.

{{rulecode serpent|DEEP SLUMBER|-1}}

Two shapes have a second, less obvious requirement. A scoped exception (Heavy Mining, Stone's Bedrock, Towering Roots' Vitality) works only if the base runs the consequences of an event inside that event's episode, as add-blight does with its Presence destruction and cascade. A late override (Swiftness of Lightning) works only if the quantity is a latest-value-wins relation (@last), so “as if it were Fast” is just a later value.

All spirits

Each spirit below quotes its special rules as printed (icons shown as labels), gives the status and mechanism, the key Turn lines with a link to their place in the source, what the run showed, and notes. Chips in the table jump to the rule.

The forks that wrote the spirits also had to add rulebook machinery that the base slice lacks: Energy, Damage and Health, Range and targeting, Growth, Events, presence tracks, and Time Passes. That work is marked BASE-EXT in each file. It is additive, but it was written several times under different names, so the spirit files run one at a time against core.t and do not yet all load together. Merging those into one shared library is the obvious next step.

Language findings

These are the problems that came up across many spirits, ranked by how often they decided a rule's status.

1. Simultaneous firings can't see each other

Rules that fire at the same moment run as siblings, and none sees the others' effects. This produced wrong results in at least six places:

  • Two Ravages missed a Blight cascade (base rules).
  • Two Dahan moved by one Push both took the same Presence (Thunderspeaker, Sharp Fangs).
  • Per-Dahan firings destroyed the same Presence twice (Sworn to Victory).
  • Two Blight additions in one land destroyed the same Presence (Finder).
  • Damage to the land and to Dahan ran in parallel, so “Dahan present” couldn't see the Ravage's kills (Hearth-Vigil).

Every fix was the same: a hand-written loop that picks one item, acts on it, then continues.

2. There is no Action

The rulebook counts and groups by Action: “max. once per Action” (Shifting Memory), “if you add multiple Presence at the same time, only once” (Heart of the Wildfire), “your Actions” (Wandering Voice), and “Spirit effects” (Destructive Nature).

Turn has no Action to key on, and episode ids can't be bound. Where it worked, it was because the effect ran inside a named episode (use-power S P), which also gave “who did it” for free (Responsibilities to the Dead).

3. Exceptions are always on

“You may … instead” cannot be one exception. Once installed it always replaces, and declining by re-emitting the original gets intercepted again and loops. Every optional rule asks first, in an earlier step, and installs the exception only on yes (Choke the Land, Dance of Decades).

A related problem: an exception can't be partly undone. Vengeance lets a Build happen that Disease already consumed, and had to restate the base Build rules to do it.

4. Exceptions catch their own output

A replacement that matches its own pattern loops (Badlands). One that re-emits the same relation with arguments outside the pattern is fine (Fathomless Mud). Several rules avoided re-triggering by using a lower-level verb, for example adding the Strife piece directly instead of “add Strife”. That works, but any other “when Strife is added” rule then can't see it.

5. Silent timing mistakes

The most expensive category, because nothing reports an error:

  • The rest of a rule runs inside the episode it matched, so it can't see facts that start when that episode ends (Lightning).
  • P, >q matches every earlier q, including other turns' and other offers' (Dances, Behemoth, Keeper).
  • Top-level facts never join episodes inside the game (Ocean).
  • A fact asserted from a rule anchored on another forever-fact floats where later reads can't see it (Towering Roots, Wounded Waters).
  • A ^ inside a short sub-episode is gone before its parent reads it (Shifting Memory).
  • A choice with no options quietly resolves to nothing (Breath of Darkness, Green).
  • A head variable not bound in the body becomes a fresh object (Keeper).

6. Nothing can stop being true

Tuples only grow, and turn-scoped facts need a turn key that episode ids can't supply. So these could not be expressed directly:

  • “Until changed” (Open the Ways).
  • Removing a card from a set (Days That Never Were).
  • “While the Incarna is here” as a standing guard (Heart-Tree).

Things that change were modeled as pieces at locations, which works well. Healing had to become an explicit event so it could be intercepted (Slow and Silent Death).

7. No negation, little arithmetic

Leaving things out by default is often free. The Endless Dark is “not a land” just by having no land row (Breath of Darkness). But other phrases needed workarounds:

  • “Inland”, “without Fire” and “not a Sacred Site” needed zero rows or extra board data.
  • Removing an explore source was impossible (Isolate).
  • Clamps like “min. 1 Health” aren't additive (Blistering Heat).
  • Symbol inequality, addition, subtraction and halving were all hand-written #js-defs.

8. Bugs found in the base slice

The forks found bugs in core.t itself:

  • Adding Presence moves every Presence in the supply, not one.
  • There is no Blight supply or loss condition, so cascades between two blighted lands can recurse until the step limit.
  • Blight's Presence destruction and cascade run as siblings.
  • The “ravaged” marker never resets, so later turns never Ravage.

None of these were fixed during the study, so every result was measured against the same base.

%%ISSUES%%

What to change

In the language

  1. Sequential iteration. A construct for “for each X (in an order the player chooses), do …”, written once instead of as a hand-rolled pick-next loop. The same construct would fix multi-piece moves and per-item triggers. Why: §1 simultaneity · Ravage cascade · Thunderspeaker · Sharp Fangs · Sworn to Victory · Finder · Hearth-Vigil
  2. Optional exceptions. {? p … => e}: ask a choice when the tuple is intercepted, and let a declined tuple pass through without being intercepted again. Why: §3 always on · Choke the Land · Dance of Decades · Vengeance
  3. Re-entrancy guard. A replacement is never intercepted by the exception that produced it, which would fix Badlands-style boosts. Why: §4 own output · Badlands · Fathomless Mud
  4. Actions as first-class. Bindable episode ids (or a built-in “current action root”), so “once per Action”, “at the same time” and “your Actions” have something to key on. Why: §2 no Action · Shifting Memory · Wildfire · Wandering Voice · Destructive Nature · Responsibilities to the Dead
  5. Lints for the silent traps. Warn on:
    • a rule that matches top-level facts;
    • >p where nothing bounds which p;
    • a choice whose options are always empty;
    • an unbound head variable;
    • a read inside an episode that only becomes visible after it ends.
    Why: §5 timing · Lightning · Dances · Behemoth · Keeper · Ocean · Towering Roots · Breath of Darkness · Green
  6. Interval-valued views. Turn a run of equal acc values (“the Incarna is in L”) into a tuple with an interval, usable as an exception context. Why: §6 nothing stops · Heart-Tree · Open the Ways
  7. Small built-ins. Symbol neq, integer arithmetic, and stratified negation in acc bodies. Why: §7 negation, arithmetic · Isolate · Blistering Heat · Breath of Darkness

In the way the rules are written

  • Every noun the rulebook uses gets a named view, and nothing reads it inline. Examples: land-for, terrain-for, sacred-site, beasts-at, speed, health, push-dest, presence-source.
  • Every quantity is a sum of contributions, each tagged with its cause.
  • Every verb is its own episode and carries its actor: move, add-blight, destroy, heal, build, add-strife, use-power, growth.
  • Every choice is named, so other rules can constrain it.
  • Steps the rulebook orders are ordered with ~>; nothing that can interact is left as siblings.
  • One shared library for the rulebook machinery the forks each rewrote (Energy, Damage and Health, Range, Growth, Events, Time Passes, turn numbers), so all 37 spirit files can load together.
