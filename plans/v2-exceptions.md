# exceptions

*Exceptions* let a rule locally override what a predicate does. The
surface form is an **exception expression** `{p t1..tn => q s1..sm}`
written inside a rule body. The separator is `=>` (not `->`) to avoid
clashing with the aggregate weight arrow. Neither atom carries a
marker. Intuition: "in the context this expression occurs in, wherever
`p t1..tn` would have been produced, produce `q s1..sm` instead."

Worked example from `notes/overview.md`:

```
activate.it.is misfits
  ~choose.it _X, !in-supply _X;
  is _X X
  ~play-card.it.^is X
    {move X _ => nope}
```

The feature is a **source-to-source transformation on the rule set**,
run once before any expansion. No evaluator semantics change. It is
built on the already-implemented `bool` aggregate (see
[[v2-bool-aggregate]]): each exception's flag is a nullary `bool`
relation.

## Per-exception desugaring

Process every exception expression in the program **in sequence** (a
total order; source order). For each one `{p t1..tn => q s1..sm}`
occurring in rule `R`, with `p'` and `p_exn` freshly minted *per
exception*:

1. Add the schema declaration `#acc p_exn -> bool`. `p_exn` is nullary
   — purely a boolean flag.
2. **Rewrite every positive (asserted) occurrence of `p` to `p'`,
   across the whole current rule set** — including rules generated by
   *earlier* exceptions (this is what makes chaining work, below).
   Producers now emit `p'`; consumers (queries of `p`) are untouched
   and read the `p` re-emitted by the generated default rule.
3. In `R`, replace the exception expression with an anchored flag
   assertion `^p_exn -> 1`. This sets the flag over `R`'s anchor
   context — the moment range the exception applies to.
4. Append an **exception rule**: `p' t1..tn, p_exn -> 1, ^q s1..sm`
   (match `p'`, the flag is set, assert the override `q`).
5. Append a **default rule**: `p' V1..Vn, p_exn -> 0, ^p V1..Vn`, where
   `V1..Vn` are fresh distinct variables and `n` is `p`'s arity (match
   *any* `p'`, the flag is unset, re-emit the real `p`).

Steps 3–5 add `^q` / `^p` *after* the step-2 rewrite, so those keep the
literal `q` / `p`.

Net effect: a produced `p'` tuple is re-emitted as `p` unless the flag
`p_exn` is set within that tuple's moment range, in which case the
exception rule emits `q` instead.

### Why the flag is nullary (no copied `t1..tn`)

What scopes *which* `p'` tuples are excepted is **moment overlap**, not
argument matching. The `bool` query `p_exn -> 1` in the exception rule
is evaluated within the matched `p'` tuple's moment range, and
`^p_exn -> 1` set the flag at the declaring rule's anchor — so only
`p'` produced in that same temporal context sees the flag as true.
Copying `p`'s argument terms onto the flag would be redundant with the
moment scoping and would misbehave for constant/wildcard `t_i` (e.g.
`move X _`).

### Why the default rule uses fresh `V1..Vn`

Per `notes/overview.md`: the default rule "matches any tuple, not just
the ones matching the terms used in the exception case." Reusing the
exception's `t1..tn` would re-emit `p` only for arguments matching that
pattern, dropping every other `p'`. The exception rule, by contrast,
needs the literal `t/s` terms so `q`'s free variables bind from `p`'s
and only matching `p'` instances fire `q`.

### Multiple exceptions chain automatically

Because each exception completes fully (including a default rule that
positively asserts `p`) before the next is processed, a later
exception's step-2 rewrite catches the earlier default's `^p`. For
`{p => q}` then `{p => r}` (fresh `p'1`/`p1_exn`, `p'2`/`p2_exn`):

```
exc1:  p'1 .. , p1_exn -> 1, ^q          -- from {p => q}
def1:  p'1 V.., p1_exn -> 0, ^p'2 V..    -- ^p was rewritten to ^p'2 by {p => r}
exc2:  p'2 .. , p2_exn -> 1, ^r          -- from {p => r}
def2:  p'2 V.., p2_exn -> 0, ^p  V..
```

Producers emit `p'1`; def1 forwards to `p'2` (unless `q` intercepts);
def2 forwards to the real `p` (unless `r` intercepts). The layering is
purely a consequence of sequential application — no special-casing of
same-`p` exceptions is needed.

## Surface syntax & parsing (`ts/src/v2/parse.ts`)

### Tokenizer

Add a `{ ... }` block. At `atomStart`, on `ch === "{"`, scan to the
matching `}` (track `{`/`}` depth), and emit a new token:

```typescript
| { tag: "exception"; text: string; line: number }   // inner text, braces stripped
```

`}` outside a block, or an unterminated `{`, is a tokenize error.

### Atom parsing

Split the inner `text` on the **top-level `=>`** into `leftText` /
`rightText` (mirror `findTopArrow` with a `=>` matcher — a depth-0
scan).

- **Left side (`p t1..tn`)**: parse via `tokenizeTermText` +
  `parseTerms` into an `Atom`. A top-level `->` here is an **error** —
  the LHS may not be an aggregate (`{p .. -> X => ..}` is rejected at
  parse). The LHS is a plain predicate pattern.
- **Right side (`q s1..sm` or `q s1..sm -> W`)**: parse with the
  aggregate-aware logic (reuse `parseAtomText`'s `findTopArrow` weight
  split), capturing an optional trailing `-> W`. The RHS *may* be an
  aggregate / bool assertion — `q` is asserted `^q s1..sm -> W` in the
  generated exception rule.

Other errors: missing `=>`; either side empty; either head not a
`Symbol`; a marker char leading either side. Produce a new
**pre-expand-only** `RuleAtom` variant (add to `ts/src/v2/types.ts`):

```typescript
| { tag: "Exception"; left: Atom; right: Atom; rightWeight?: Term; span: Span }
```

Wrap it as a `BodyItem` of `kind: "atom"`.

### Body / desugar plumbing

- `collectUsedNames` (parse.ts:463): descend into `left`/`right` terms.
- `desugarBody` (parse.ts:536): treat `Exception` as an opaque
  pass-through item — not a valid dot left or dot right (a `.` adjacent
  to an exception block is a parse error), and not a frame anchor. Emit
  it unchanged so the exceptions pass can see it.
- Any other structural walk switching on `a.tag` (`"Atom"` / `"Sub"` /
  `"Equal"`) gets an `Exception` arm.

The block typically appears as a plain continuation-line body item (as
in the worked example), so it inherits the surrounding anchor context
once its replacement atom is produced by anchor decomposition.

## The transformation pass (`ts/src/v2/expand.ts`)

Add `applyExceptions(program: Program): Program` and call it at the top
of `expand` (expand.ts:15), before `decomposeRule`. `expand` is the
sole consumer of pre-expand programs (only call site: fixpoint.ts:32).

```typescript
export function expand(program: Program): Program {
  program = applyExceptions(program);
  ...   // existing body unchanged
}
```

Algorithm:

1. Collect every `Exception` atom in source order, walking into `Sub`
   bodies (Subs survive into pre-expand IR — expand.ts:332). Record each
   with a mutable handle to its position so step 3 below can replace it.
   If none, return `program` unchanged (zero overhead).
2. For each exception, in order:
   - Mint fresh `p'` / `p_exn` against the set of all symbol names used
     so far (suffix `'` / `_exn`, counter fallback on collision; both are
     *suffixes*, so they avoid the reserved `*`/`_` *prefix* rule at
     parse.ts:710). `n` = `p`'s arity, taken from the exception's left
     atom (`t1..tn`).
   - `schema.set(p_exn, "bool")`.
   - Walk all current rule bodies (incl. Subs and rules appended by
     earlier exceptions); for each pre-expand `Atom` whose head is `p`
     **and whose marker is an assertion** (`fact | episode | anchor |
     ask`), rewrite the head to `p'`. Leave `match` / `aggregate` /
     `constrain` sub-atoms (all queries) as `p`.
   - Replace this exception's `Exception` atom with
     `{ tag:"Atom", marker:"anchor", atom:{terms:[sym(p_exn)]}, weight: sym("1"), span }`.
   - Append the exception rule and default rule (below) to
     `program.rules`, naming them as described under **Naming**.

Generated rule bodies (pre-expand atoms):

```
exception rule:                          default rule:
  match     p'   t1..tn                    match     p'   V1..Vn
  aggregate p_exn -> 1                      aggregate p_exn -> 0
  anchor    q    s1..sm  [-> W]             anchor    p    V1..Vn
```

The two `aggregate p_exn` atoms are `{marker:"aggregate",
atom:{terms:[sym(p_exn)]}, weight: sym("1"|"0")}`. The exception rule's
`anchor q` carries the RHS weight when the exception's `rightWeight` is
set: `{marker:"anchor", atom:{terms:[sym(q), ...sTerms]}, weight: rightWeight}`.

Downstream `decomposeRule` / `splitRule` / delta-variant passes handle
these synthesized rules exactly like hand-written ones.

### Naming

`resolveRuleNames` (parse.ts:438) runs at parse time, so every source
rule already has a resolved `.name` when `applyExceptions` runs (an
explicit `f` from `#def f`, or an auto `r<N>`). Derive the generated
names from the containing rule's `.name` and set `.name` directly (the
resolution pass has already happened — do **not** leave `name:""`):

```
#def f ... { ... } ...     ⇒     f          (the rewritten source rule)
                                 f_exn      (the exception rule)
                                 f_default  (the default rule)
```

When one rule contains more than one exception, suffix to keep names
unique: `f_exn`, `f_exn2`, … and `f_default`, `f_default2`, …. Guard
against collisions with existing rule names.

## Bool-aggregate reuse

The flag is a `bool` relation, so empty-group → `0`, any assertion →
`1`, and the `-> 0` / `-> 1` query forms are already implemented. The
synthesized flag atoms are built after parse-time bool validation, so
they bypass that pass — they are constructed correct by hand.

## Open considerations (later, not this change)

- **Rule ordering** (overview's existing question): allowing the full
  rule set to be ordered so a rule later than exception `E` is not
  rewritten by it. Out of scope.

(The "`p` itself aggregated" question is resolved: the exception's LHS
may not be an aggregate — `{p .. -> X => ..}` is rejected at parse —
while the RHS may carry an aggregate assertion. See **Atom parsing**.)


## Tests (`ts/data/v2/exceptions.t`)

1. Basic override: a producer of `p` in the exception context yields
   `q`; a producer in a disjoint moment range falls through the default
   and stays `p`.
2. Free-variable binding: `{p X => q X}`; `q` receives `X` from `p`.
3. Error: free variable in the RHS not bound by the LHS.
4. Error: non-symbol head / marker char on either side.
5. Wildcard `t_i` (`move X _`): the `_` never reaches the nullary flag;
   the exception rule's `p' X _` + `^q` overrides regardless of arg 2.
6. Chaining: two exceptions on the same `p` (`{p => q}`, `{p => r}`) in
   distinct contexts each intercept their own context; a producer in
   neither context stays `p`.
7. RHS aggregate: `{p => q => W}` (RHS is a bool/aggregate assertion);
   the generated exception rule asserts `^q .. -> W`.
8. Error: aggregate on the LHS (`{p a -> X => q}`) is rejected at parse.
9. Naming: `#def f ... { ... }` yields rules named `f`, `f_exn`,
   `f_default`.
10. Nested-in-dot-chain context (reduced `misfits` example).
11. No-exception program is unchanged through `applyExceptions`.
